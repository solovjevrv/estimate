# E2E (Playwright)

Полный стек в браузере: собранный `@estimate/server` + дев-сервер `@estimate/web` (его прокси
на `/api`/`/socket.io` избавляет от отдельного nginx) + настоящая PostgreSQL.

## Два набора

- **Smoke** (`--grep @smoke`) — golden path целиком: вход → комната → гость по ссылке →
  голосование → вскрытие карт. Гоняется в CI как обязательный чек на каждый PR в `main`
  (гейт релиза).
- **Регрессия** (без фильтра) — остальные сценарии по фичам, по одному spec-файлу на
  область. Гоняется ночным cron'ом и вручную (`workflow_dispatch`), не на каждый PR —
  чтобы не тормозить обычную работу с `dev`.

Новую фичу — новый/расширенный spec в регрессионном наборе; в smoke попадает только
golden path.

## Аутентификация в тестах

Настоящий OAuth (Google/Яндекс) в CI не автоматизировать — чужой UI, капчи, нужны
реальные аккаунты. Вместо этого хелпер `loginAs()` (`src/fixtures.ts`) минтит валидный
JWT тем же `TokenService`/секретом (`JWT_SECRET`), что и у поднятого сервера, и
подставляет его как cookie в browser context — экран логина не участвует. Пользователь
создаётся напрямую в БД (`createUser()`), минуя OAuth-провайдера.

## Переменные окружения

Нужны те же, что для `pnpm dev` (берутся из корневого `.env`, если он есть, иначе — из
окружения CI):

- `DATABASE_URL` — тестовая PostgreSQL (миграции накатываются автоматически перед
  прогоном, `src/global-setup.ts`).
- `JWT_SECRET` — должен совпадать с секретом, под которым поднимается тестируемый
  сервер (тот же `.env`, поэтому по умолчанию так и есть).

## Запуск

```bash
pnpm --filter @estimate/server build   # один раз, если dist/ ещё не собран
pnpm test:e2e            # весь набор
pnpm test:e2e:smoke      # только smoke
```

Если на портах 3000/5173 уже что-то слушает (например, свой `pnpm dev`) — Playwright
локально переиспользует уже запущенные серверы (`reuseExistingServer`), в CI всегда
поднимает свои.

## Очистка данных

Тесты не переиспользуют данные друг друга и не полагаются на пустую БД: у комнат имя
всегда начинается с `E2E `, у пользователей — почта на домене `@estimate-e2e.test`. По
этим маркерам `src/global-teardown.ts` подчищает всё после прогона — даже если тест
упал, а не только при успехе.
